# Flow of Events — ToDoList System

Документ описывает потоки событий (Flow of Events) для каждого варианта использования (Use Case) в системе **ToDoList**.  
Каждый UC описывает: краткое описание, предусловия, основной поток, альтернативные потоки и постусловия.

---

## **UC1 — Register (Регистрация пользователя)**

**Краткое описание:**  
Позволяет новому пользователю создать учётную запись с помощью Auth Service.

**Предусловия:**  
- Пользователь не зарегистрирован.  
- Auth Service доступен.

**Основной поток:**
1. Пользователь открывает страницу регистрации.
2. Интерфейс отображает поля: имя, email, пароль, подтверждение пароля.
3. Пользователь заполняет данные.
4. Пользователь нажимает «Зарегистрироваться».
5. Система отправляет данные в Auth Service.
6. Auth Service проверяет корректность данных.
7. В случае успеха создаётся учётная запись.
8. Пользователь перенаправляется на страницу входа.

**Альтернативные потоки:**  
- **A1:** Email уже существует → сообщение «Email уже зарегистрирован».  
- **A2:** Есть пустые поля → подсветка полей и сообщение «Заполните все обязательные поля».  
- **E1:** Ошибка сервера → «Не удалось выполнить регистрацию».

**Постусловия:**  
- Создан новый пользователь.

## **UC2 — Login (Вход в систему)**

**Краткое описание:**  
Позволяет зарегистрированному пользователю войти в систему.

**Предусловия:**  
- Пользователь зарегистрирован.  
- Auth Service доступен.

**Основной поток:**
1. Пользователь открывает страницу входа.
2. Интерфейс отображает поля email и пароль.
3. Пользователь вводит данные.
4. Пользователь нажимает «Войти».
5. Система отправляет данные в Auth Service.
6. Auth Service проверяет учётные данные.
7. При успехе возвращается JWT.
8. Система создаёт сессию и открывает страницу задач.

**Альтернативные потоки:**  
- **A1:** Неверные данные → «Неверный email или пароль».  
- **E1:** Ошибка сервера → «Не удалось выполнить вход».

**Постусловия:**  
- Пользователь авторизован.

## **UC3 — Create Task (Создание задачи)**

**Краткое описание:**  
Создание новой пользовательской задачи.

**Предусловия:**  
- Пользователь вошёл в систему.

**Основной поток:**
1. Пользователь нажимает кнопку «Добавить задачу».
2. Интерфейс отображает форму создания задачи.
3. Пользователь заполняет данные: название, описание, дату, категорию.
4. Пользователь нажимает «Сохранить».
5. Система проверяет корректность введённых данных.
6. Система сохраняет задачу.
7. Интерфейс обновляет список задач.

**Альтернативные потоки:**  
- **A1:** Название пустое → «Название задачи обязательно».  
- **A2:** Дата/время в прошлом → сообщение об ошибке.  
- **E1:** Ошибка сервера → «Не удалось создать задачу».

**Постусловия:**  
- Задача создана.

## **UC5 — Delete Task (Удаление задачи)**

**Краткое описание:**  
Удаление задачи пользователем.

**Предусловия:**  
- Пользователь вошёл.  
- Задача существует.

**Основной поток:**
1. Пользователь выбирает задачу.
2. Нажимает «Удалить».
3. Система запрашивает подтверждение.
4. Пользователь подтверждает.
5. Система удаляет задачу.
6. Интерфейс обновляет список задач.

**Альтернативные потоки:**  
- **A1:** Пользователь отменяет удаление.  
- **E1:** Ошибка сервера → «Не удалось удалить задачу».

**Постусловия:**  
- Задача удалена.

## **UC8 — Create Group (Создание группы)**

**Краткое описание:**  
Создание новой группы задач.

**Предусловия:**  
- Пользователь вошёл.

**Основной поток:**
1. Пользователь нажимает «Создать группу».

**Постусловия:**

## **UC9 — Invite User (Пригласить пользователя)**

**Краткое описание:**  
Добавление участников в группу.

**Предусловия:**  
- Группа существует.  
- Пользователь — владелец или администратор группы.

**Основной поток:**
1. Пользователь открывает страницу группы.
2. Нажимает «Пригласить пользователя».
3. Вводит email приглашённого.
4. Система проверяет пользователя.
5. Система отправляет приглашение.

**Альтернативные потоки:**  
- **A1:** Пользователь уже участник → сообщение.  
- **E1:** Ошибка сервера → «Не удалось отправить приглашение».

**Постусловия:**  
- Приглашение отправлено.

## **UC10 — Assign Task (Назначение задачи)**

**Краткое описание:**  
Назначение задачи участнику группы.

**Предусловия:**  
- Группа существует.  
- Участник и задача существуют.

**Основной поток:**
1. Пользователь выбирает задачу.
2. Выбирает участника.
3. Нажимает «Назначить».
4. Система связывает задачу с участником.
5. Интерфейс обновляется.

**Альтернативные потоки:**  
- **E1:** Ошибка сервера.

**Постусловия:**  
- Задача назначена участнику.
