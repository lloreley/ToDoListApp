# ToDoList - Диаграмма классов и описание модели

## Обзор
Этот документ описывает ключевые сущности и их взаимосвязи в доменной области приложения ToDoList, основанные на структуре базы данных и архитектуре системы.
Данная модель служит концептуальной основой для объектно-ориентированной реализации приложения, а также определяет структуру хранения данных.

## Class Diagram Description
Основные объекты системы — пользователи, их задачи, группы задач и распределение пользователей по группам.

## User (Пользователь)
Представляет зарегистрированного пользователя системы.

### Атрибуты:
- `id` — PK  
- `email` — почта пользователя  
- `first_name` — имя  
- `last_name` — фамилия  
- `password` — пароль  
- `phone` — телефон  
- `role` — роль (например: USER, ADMIN)

### Связи:
- Один пользователь → много личных задач (`tasks`)
- Один пользователь → много назначенных групповых задач (`group_tasks.assigned_user_id`)
- Пользователь может состоять в нескольких группах (`user_group`)

---

## Task (Личная задача)
Задача, принадлежащая конкретному пользователю.

### Атрибуты:
- `id` — PK  
- `title` — заголовок  
- `content` — описание  
- `is_completed` — выполнена или нет  
- `is_important` — важна или нет  
- `task_deadline` — дедлайн  
- `user_id` — FK → User

### Связи:
- Принадлежит одному пользователю

---

## Group (Группа задач)
Группа объединяет пользователей и содержит групповые задачи.

### Атрибуты:
- `id` — PK  
- `name` — название группы  
- `description` — описание  
- `created_date` — дата создания

### Связи:
- У группы много пользователей (`user_group`)
- У группы много групповых задач (`group_tasks`)

---

## GroupTask (Групповая задача)
Задача, назначенная в рамках группы.

### Атрибуты:
- `id` — PK  
- `title` — заголовок  
- `content` — содержание  
- `is_completed` — выполнена или нет  
- `is_important` — важна или нет  
- `task_deadline` — дедлайн  
- `group_id` — FK → Group  
- `assigned_user_id` — FK → User

### Связи:
- Принадлежит группе  
- Может быть назначена конкретному пользователю

---

## UserGroup (Связь пользователь–группа)
Связующая таблица для связи «многие-ко-многим».

### Атрибуты:
- `group_id` — FK → Group  
- `user_id` — FK → User

### Связи:
- Пользователь может состоять в нескольких группах  
- Группа может содержать множество пользователей

---

## UserRoles (Роли пользователя)
Дополнительная таблица с перечислением ролей пользователей.

### Атрибуты:
- `user_id` — FK → User  
- `roles` — наименование роли

### Использование:
Позволяет хранить несколько ролей на одного пользователя при необходимости.

---

# Основные связи в системе

### 1. User — Task (Один ко многим)
Пользователь может иметь множество личных задач.

### 2. User — GroupTask (Один ко многим)
Пользователю может быть назначено множество групповых задач.

### 3. Group — GroupTask (Один ко многим)
Каждая групповая задача принадлежит конкретной группе.

### 4. User — Group (Многие ко многим)
Реализовано через таблицу `user_group`.

### 5. User — Role (Один ко многим)
Если требуется расширенная система ролей.
